## Scope

Show how busy each corridor is right now, from server data only: how many trades
are waiting, how long a payout typically takes, and the corridor's health.

**Key components**
- Queue depth per corridor
- Estimated settlement time per corridor
- Corridor health (reuses the F1 rates health levels)
- Lives in the **Rates** tab of the app shell (`nav.rates`)

**Product rule (enforced)**: every number is the server's. The app never
estimates, smooths or invents queue data (rules 2 and 5). Without the endpoint
the screen says "Market depth is not connected yet." and shows nothing else.

## Contract (`docs/api_contract.md`)

```
GET /api/v1/market/depth        (needs login)
{
  "asOf": "<ISO-8601 UTC>",                      (optional, not displayed yet)
  "corridors": [
    {
      "from": "<currency code>",
      "to": "<currency code>",
      "queueDepth": <int>,
      "estimatedSettleSeconds": <int>,
      "status": { "code": "<status code>", "level": "healthy | limited | down" }   (optional)
    }
  ]
}
```
- Corridors naming a currency missing from `/config` are skipped (same rule as
  `/rates`).
- `status.code` is translated when the app knows it (`corridor.status.<code>`),
  otherwise the level wording is used.
