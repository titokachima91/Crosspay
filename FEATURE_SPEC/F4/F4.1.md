## Scope

Give users their transaction history from server data: a filterable, searchable ledger plus export and analytics.

**Key components (plan)**
- Transaction history with filters
- Search by trade reference or recipient
- Status-change timeline
- Export (CSV minimum)
- Spending analytics aggregated by corridor / currency

**Product rule (enforced)**: no mocks, nothing hardcoded in `lib/` - the history screen shows a plain "not connected" state until the backend ships the history endpoints.

## Shipped 2026-11-07

**Date-range filter** on the history screen - client-side over the server rows already loaded (the server stays the source of truth; no rows are invented):

- `HistoryRange` enum (`all` / `last7` / `last30` / `last90`) with `includes(createdAt, now)`. Compared as instants, so UTC rows from the server line up with the device clock; `all` never filters a row out.
- `_RangeChips` - a `Wrap` of `ChoiceChip`s ("All time" / "Last 7 days" / "Last 30 days" / "Last 90 days") under the status chips; default is "All time".
- `_apply(trades, now)` now runs status filter -> date window -> search; all three combine, and an empty result still says "No trades found.".
- Fixed a pre-existing layout bug found while testing: the status chip `Row` overflowed by 69px at the 432px content width (yellow/black stripes on a real phone). Both chip rows are now `Wrap`s, so every option is visible and tappable at any width instead of being clipped.
- Tests: `test/transaction_history_screen_test.dart` - 2 unit tests for `HistoryRange` boundaries + 6 widget tests (default list, window hides older rows, window + status combined, search, empty window message, "not connected" state). Fakes live only in `test/`.

## Shipped 2026-11-07 (part 2 - timeline, export, analytics)

**a) Status timeline** (`GET /trades/{id}/history`)

- `lib/models/trade_event_model.dart` -> `TradeEvent{status, at, noteCode}`.
- `lib/repositories/status_parser.dart` -> one `parseTradeStatus()` shared by the
  trade parser and the timeline (an unknown code is still an error, never a guess).
- `lib/repositories/trade_repository.dart` -> `fetchTimeline(tradeId)`.
- `lib/providers/trade_timeline_provider.dart` -> `idle/loading/ready/unavailable/error`.
- `lib/features/transaction/widgets/trade_timeline_card.dart` -> dotted list with
  local times; wired into the tracker under `TradeStatusBar`.

**b) CSV export** (`GET /trades/export`)
- `ExportTicket{downloadUrl, expiresAt}` on the trade model; `requestExport()` in
  the repository; `lib/providers/trade_export_provider.dart`.
- History screen: download icon -> bottom sheet with the link + **Copy link**
  (`Clipboard`). **No new dependency**: the file is built and served on the
  server; the app only hands the link over.

**c) Spending analytics** (`GET /trades/analytics`)
- `lib/models/analytics_model.dart` (`TradeAnalytics`, `CorridorSpend`),
  `fetchAnalytics(config)`, `lib/providers/analytics_provider.dart`,
  `lib/features/ledger/screens/analytics_screen.dart` (`/analytics`, reachable
  from the Account hub and from the history AppBar).

**d) Wiring and localization**
- The **Ledger** shell tab is now the real history screen (placeholder removed).
- `TradeStatus` gained `code` / `labelKey`; all new and touched strings moved into
  `lib/core/localization/en.json` + `sw.json` (176 -> 261 keys, both files in sync).
- `lib/core/utils/date_format.dart` is the one place dates and durations are
  formatted now (the history screen's private month table was removed).

**Tests (all new this pass)**: `test/trade_timeline_test.dart` (2 unit + 4 widget),
`test/trade_export_test.dart` (2 unit + 1 widget), `test/analytics_screen_test.dart`
