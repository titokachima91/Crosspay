**Key components (plan)**

## Shipped 2026-11-07

**Date-range filter** on the history screen - client-side over the server rows already loaded (the server stays the source of truth; no rows are invented):

- `HistoryRange` enum (`all` / `last7` / `last30` / `last90`) with `includes(createdAt, now)`. Compared as instants, so UTC rows from the server line up with the device clock; `all` never filters a row out.
- `_RangeChips` - a `Wrap` of `ChoiceChip`s ("All time" / "Last 7 days" / "Last 30 days" / "Last 90 days") under the status chips; default is "All time".
- `_apply(trades, now)` now runs status filter -> date window -> search; all three combine, and an empty result still says "No trades found.".
- Fixed a pre-existing layout bug found while testing: the status chip `Row` overflowed by 69px at the 432px content width (yellow/black stripes on a real phone). Both chip rows are now `Wrap`s, so every option is visible and tappable at any width instead of being clipped.
- Tests: `test/transaction_history_screen_test.dart` - 2 unit tests for `HistoryRange` boundaries + 6 widget tests (default list, window hides older rows, window + status combined, search, empty window message, "not connected" state). Fakes live only in `test/`.
