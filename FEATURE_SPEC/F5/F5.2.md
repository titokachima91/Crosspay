# F5.2 Saved Recipients CRUD

**Plan of record**: PART 1 -> F5 Profile & Security -> F5.2 (`MASTER_PROGRESS_REPORT.md`)
**Status**: FRONTEND SHIPPED 2026-11-07 - awaiting backend write endpoints
**Owner**: CrossPay Engineering Team

## Scope

Create, read, edit and delete the people and businesses the user pays.

**Key components**
- List of saved recipients (name, rail, account or phone, verified tick)
- **Add** (form: name, payout rail from `/config`, account or phone)
- **Edit** (same form, pre-filled)
- **Delete** (confirm first)
- Entry point: Account hub -> "Saved recipients" (`/recipients`)

**Product rules (enforced)**: the list is only ever what the server returned -
the app never edits its own copy and never shows a recipient the server did not
save (rule 2 and 5). Recipient names come from the user, not from a name check
(rule 10). While the endpoints are missing the screen says "Saved recipients are
not connected yet." and offers no fake rows and no add button.

## Contract (`docs/api_contract.md`)

```
GET    /api/v1/beneficiaries            (needs login)
       -> { "beneficiaries": [ { "id": "...", "railId": "...", "name": "...",
                                 "accountOrPhone": "...", "kycVerified": true } ] }
POST   /api/v1/beneficiaries            (needs login, X-Idempotency-Key)
       { "railId": "...", "name": "...", "accountOrPhone": "..." }
       -> the saved recipient object (same shape as one item above)
PATCH  /api/v1/beneficiaries/{id}       (needs login)
       { "railId": "...", "name": "...", "accountOrPhone": "..." }
       -> the updated recipient object
DELETE /api/v1/beneficiaries/{id}       (needs login)
       -> 204, no body
```
- `railId` must exist in `/config.payoutRails`; an unknown rail is a broken
  response and is never guessed.
- The app sends the account/name in the body (never in the address) and never
  logs them.
